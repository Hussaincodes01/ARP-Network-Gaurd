ARPGuard: catches devices that lie about their network address

On a home or office network, any device can falsely announce I am the router. Traffic then flows through the attacker (a man-in-the-middle). ARPGuard spots this by combining simple rules, an anomaly-detecting AI model and a plain-English explanation.

    What is ARP?
    
              
    Programs talk to IP addresses (like 192.168.1.1), but network cards deliver data to MAC addresses (like 50:c7:bf:3a:1c:01). ARP (Address Resolution Protocol) connects the two:
    
              
      
                
    1. Your laptop shouts to everyone: Who has 192.168.1.1?
      2. 
                
    2. The router answers: 192.168.1.1 is at 50:c7:bf:3a:1c:01.
      3. 
                
    3. Your laptop writes that in its ARP cache (its address book).
      4. 
              
    
              
    What goes wrong?
    
              
    ARP has no password and no proof. Any device can send an answer, even when nobody asked, and everyone believes it. An attacker keeps saying 192.168.1.1 is at my MAC. Your traffic then goes to the attacker, who quietly forwards it so nothing looks broken. This is ARP spoofing, and it lets the attacker read or change your traffic.
    
            
    
            
    
              
    How ARPGuard catches it
    
              
    
                
    1. The rule checker
    Keeps the address book and raises an alarm when an IP suddenly "moves" to another device, especially the router's IP.
    
                
    2. The AI anomaly model (Kitsune)
    Learns what normal traffic looks like, then notices when traffic suddenly behaves strangely, for example when it's relayed through an attacker.
    
                
    3. The judge
    Combines the two. Rule alarm and strange traffic means an attack. Rule alarm but normal traffic is probably a new device.
    
                
    4. The explainer
    An AI writes what happened and how to fix it. It only explains; it never decides.

    Glossary
    
          
    
            
    IP address
    A device's address on the network, like 192.168.1.10. Programs use these.
    
            
    MAC address
    The hardware ID burned into a network card, like b8:ac:6f:52:7e:10. The first half tells you the maker (Dell, Apple, VMware…).
    
            
    ARP
    Address Resolution Protocol: the system that answers "which MAC address has this IP?" on a local network.
    
            
    ARP cache
    Each device's private address book of IP → MAC answers it has heard.
    
            
    Gateway / router
    The device that connects your network to the internet (here 192.168.1.1). The favorite target, because all internet traffic goes through it.
    
            
    ARP spoofing
    Sending fake ARP answers so other devices send their traffic to the attacker.
    
            
    Man-in-the-middle (MitM)
    An attacker secretly sitting between two devices, able to read or change what they send.
    
            
    DHCP
    The service (usually in the router) that hands out IP addresses to devices when they join.
    
            
    Kitsune
    A published AI anomaly detector for network traffic. It learns "normal" on the fly and scores how unusual each packet is.
    
            
    Anomaly score
    How badly the model can rebuild a packet's statistics. Normal traffic scores low; strange traffic scores high.
    
            
    Threshold (alarm line)
    The score above which a packet counts as unusual. Set from the scores seen while the model was learning.
    
            
    False positive
    An alarm about something harmless, like a new printer. ARPGuard tries hard to avoid these.
    
            
    Dynamic ARP Inspection (DAI)
    A switch feature that blocks fake ARP answers. The best real fix.
    
            
    pcap
    A file containing recorded network traffic, made by Wireshark or tcpdump.
    
          
    
        
    
      
    
    
    
  
    

  
    
    
    
      
     ARP can't be fixed by itself, but these protections stop the attack. The first two are the strongest and work together.
    
      
    
        
    1. Turn on Dynamic ARP Inspection (DAI) on the switch
    The switch checks every ARP message against its list of who really owns each IP, and drops fake ones before they reach anyone.
    ip arp inspection vlan 10
interface Gi0/1
 ip arp inspection trust
    
        
    2. Turn on DHCP snooping
    Builds that trusted "who owns which IP" list from the router's DHCP replies, and blocks fake DHCP servers too.
    ip dhcp snooping
ip dhcp snooping vlan 10
interface Gi0/1
 ip dhcp snooping trust
    
        
    3. Limit devices per switch port (port security)
    One cable can't pretend to be a whole room of computers.
    interface Gi0/5
 switchport port-security
 switchport port-security maximum 2
 switchport port-security violation restrict
    
        
    4. Pin the router's MAC on important computers
    A fixed (static) ARP entry can't be overwritten by fake answers.
    arp -s 192.168.1.1 50:c7:bf:3a:1c:01
netsh interface ipv4 add neighbors "Ethernet" 192.168.1.1 50-c7-bf-3a-1c-01
    
        
    5. Use encryption everywhere
    HTTPS, SSH and VPNs keep intercepted traffic unreadable. Never click through a certificate warning: it can be a sign of this attack.
    
        
    Next: IPv6
    IPv6 replaces ARP with "Neighbor Discovery", which has the same weakness. Switch features called RA Guard and ND Inspection protect it.
